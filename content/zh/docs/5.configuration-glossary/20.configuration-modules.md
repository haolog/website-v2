# modules 属性

模块是 Nuxt 的扩展功能，可以扩展其核心功能并添加无限的集成。[了解更多](/docs/directory-structure/modules)

---

- 类型: `Array`

示例 (`nuxt.config.js`)：

```js
export default {
  modules: [
    // 使用包名
    '@nuxtjs/axios',

    // 相对于项目 srcDir 的路径
    '~/modules/awesome.js',

    // 传递选项
    ['@nuxtjs/google-analytics', { ua: 'X1234567' }],

    // 内联定义
    function () {}
  ]
}
```

模块开发者通常会提供额外所需的步骤和使用详情。

Nuxt 会尝试使用 node 的加载路径（`node_modules` 中）解析模块数组中的每个元素。如果使用了 `~` 别名，则从项目的 `srcDir` 解析。模块按顺序执行，因此顺序很重要。

**注意：** 模块注入的插件会被添加到插件列表的 *开头*。可选方案：
- 手动将自己的插件添加到插件列表末尾（`this.nuxt.options.plugins.push(...)`）
- 如果依赖其他模块，则反转模块顺序

模块应导出一个用于增强 nuxt 构建/运行时的函数，并在必要时返回 promise，直到其任务完成。请注意，模块在运行时会被引入，因此如果依赖现代 ES6 特性，需要提前进行转译。

如果想了解模块的工作原理或有兴趣开发自己的模块，请参阅[模块指南](/docs/directory-structure/modules)获取更详细的信息。此外，官方[模块](https://github.com/nuxt-community/awesome-nuxt#modules)专区提供了由 Nuxt Community 制作的众多生产级模块列表。

## `buildModules`

::alert{type="info"}
此功能从 Nuxt v2.9 起可用
::

某些模块只在开发和构建时需要。使用 `buildModules` 可以加快生产环境的启动速度，并显著减少部署到生产环境的 `node_modules` 体积。请参阅各模块的文档，确认推荐使用 `modules` 还是 `buildModules`。

使用方式的区别如下：

- 在 `nuxt.config.js` 中使用 `buildModules` 代替 `modules`
- 在 `package.json` 中使用 `devDependencies` 代替 `dependencies`（`yarn add --dev` 或 `npm install --save-dev`）
