# 部署目标

## 静态托管

Nuxt 也可以作为静态站点生成器使用。静态渲染 Nuxt 应用程序，无需服务器即可获得通用应用程序的所有优势。`nuxt generate` 命令生成网站的静态版本，为每个路由生成 HTML 并将其放置在 `dist/` 目录中，从而提高性能和 SEO，并改善离线支持。

::alert{type="info"}
得益于 [Nuxt 爬虫](/docs/configuration-glossary/configuration-generate#crawler)，动态路由也会被生成。
::

对于静态站点，需要在 `nuxt.config` 文件中添加 `static` 目标。

```js{}[nuxt.config.js]
export default {
  target: 'static' // 默认为 'server'
}
```

**将 target 设置为 static 后运行 nuxt dev 将改善开发者体验：**

- 从 `context` 中移除 `req` 和 `res`
- 在 404、错误和重定向时回退到客户端渲染 [参见 SPA 回退](/docs/concepts/static-site-generation#spa-fallback)
- 服务端渲染中 `$route.query` 始终等于 `{}`
- `process.static` 为 true

::alert{type="info"}
还公开了 `process.target`，供模块作者根据用户目标添加逻辑。
::

## 服务器托管

服务器托管是指在 Node.js 服务器上运行 Nuxt。当用户打开您的页面时，浏览器向服务器请求该页面，Nuxt 处理请求，渲染页面，并将包含所有内容的结果页面发送回来。

如果您希望按请求渲染而不是在生成时预先渲染 HTML，或者需要 [serverMiddleware](/docs/configuration-glossary/configuration-servermiddleware)，则可能需要服务器托管。

::alert{type="info"}
可以使用 `ssr: false` 在服务器托管上运行 Nuxt，但 Nuxt 不会完全渲染每个页面的 HTML。如果需要服务器中间件但不需要服务端完全渲染的 HTML，可以选择此选项。
::

对于服务器托管，使用默认的 `target: 'server'`，使用 `build` 命令构建应用程序。

```js{}[nuxt.config.js]
export default {
  target: 'server'
}
```
